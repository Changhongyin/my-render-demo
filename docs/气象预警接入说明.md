# 气象预警接入说明（fetch_weather_alerts.py）

> 配套脚本：`fetch_weather_alerts.py`（根目录）｜配置模板：`.env.example`｜自测：`tests/weather_alert_test.py`
> 分工：`local_spider_v2.py` 管行情价格，本脚本只管**气象预警**，两者互不覆盖对方的字段。

## 一、现在就能做（一个账号都还没注册）

```bash
cd /Users/user/Documents/my-render-demo

# 1) 只看效果，什么都不写
python3 fetch_weather_alerts.py --mock --dry-run

# 2) 生成联调用的预览文件 public/data.mock.json（线上 data.json 一个字节都不动）
python3 fetch_weather_alerts.py --mock

# 3) 真要让线上 data.json 带上这条模拟预警（会先自动备份）
python3 fetch_weather_alerts.py --mock --write
```

`--mock` 返回的是一条**相对当前时间生成**的「暴雨橙色预警（寿光市气象台）」，
并且会在三处写明"这是模拟数据"：`meta.weather_data_kind = "mock"`、`meta.notes`、以及
`crops[].alerts.risk` 里那句话的结尾「｜⚠️ 模拟数据，仅供联调」——**不会被误当成真实预警**。

前端联调（本地起静态服务看 `public/`）：

```bash
python3 -m http.server 8080 --directory public
# 打开 http://localhost:8080/farm.html
# 想看到预警，把页面里读 /data.json 的地方临时指到 /data.mock.json（或直接用 --mock --write 覆盖线上文件）
```

## 三、`.env` 怎么填

```bash
cp .env.example .env      # 模板里有逐项注释；.env 已被 .gitignore 忽略，不会进版本库
```

### 场景 A：接口盒子（拿到接口路径名）

```ini
ALERT_PROVIDER=apihz
APIHZ_ID=你的数字ID
APIHZ_KEY=你的通讯KEY
ALERT_APIHZ_ENDPOINT=tianqiyujing          # ← 换成你在站内看到的预警接口路径名
WEATHER_LAT=36.88
WEATHER_LON=118.73
```

### 场景 B：接口盒子（拿到的是完整地址，推荐，最不容易出错）

```ini
ALERT_PROVIDER=apihz
APIHZ_ID=你的数字ID
APIHZ_KEY=你的通讯KEY
ALERT_API_URL=https://cn.apihz.cn/api/tianqi/xxxxxx.php?id={id}&key={key}&lat={lat}&lon={lon}
#                         ↑ 直接把接口文档里给的地址贴过来；{id}/{key}/{lat}/{lon} 会被自动替换
```

### 场景 C：彩云天气

```ini
ALERT_PROVIDER=caiyun
CAIYUN_TOKEN=你的token
```

⚠️ **彩云这条路有个坑，先看清楚再填**：彩云的「预警数据」是**增值服务**，免费赠送额度**不含**它。
只填 token 时脚本会明确报错并告诉你去哪开通，**不会**把"拿不到预警"伪装成"当前没有预警"：

```bash
# 自己先验一下最直观（把 {token} 换掉）。响应里有 "result":{"alert":{...}} 才算有预警权限
curl "https://api.caiyunapp.com/v2.6/{token}/118.73,36.88/realtime?alert=true"
```

| 你看到的响应 | 含义 | 怎么办 |
|---|---|---|
| `"result": {"alert": {"status": "ok", "content": [...]}}` | 有权限，正常返回预警 | 直接 `--dry-run` 验证 |
| `"result": {"alert": {"status": "ok", "content": []}}` | 有权限，**当前无生效预警** | 正常，脚本按"0 条"成功写入 |
| `"result"` 里只有 `realtime`、**没有 `alert`** | token **没有预警权限**（最常见的坑） | 到控制台为该应用开通/升级预警数据；或改用 `apihz` / `generic` |
| `{"status":"failed","error":"Rate limit exceeded"}` | 调用太快被限流（QPS 限制） | 隔一会儿再试；脚本本身带 1–3 秒随机延迟与重试 |

> 想**不花钱**就把真实预警跑通：优先用第 1 项（接口盒子）或第 5 项（`generic` 接政府开放数据平台）。
> 彩云适合作为**付费后的正式数据源**：字段最规范（CAP 标准 + 行政区划），脚本已经为它做好字段映射。

### 场景 D：任何其他平台（政府开放数据 / 自建服务）

```ini
ALERT_PROVIDER=generic
ALERT_API_URL=https://example.gov.cn/api/warnings?lat={lat}&lon={lon}
ALERT_API_HEADERS={"Authorization":"Bearer xxxxx"}
ALERT_JSON_PATH=data.list                                   # 预警数组在响应里的位置
ALERT_FIELD_MAP={"type":"warningType","level":"warningLevel","text":"warningText","pub_time":"issueTime"}
ALERT_SOURCE_LABEL=某省数据开放平台（数据来源：省气象局）
```

**优先级**：命令行参数 > 真实环境变量 > `.env` 文件 > 默认值。所以临时覆盖用命令行即可，例如：
`python3 fetch_weather_alerts.py --lat 36.70 --lon 117.00 --no-delay`

## 四、填完之后怎么验证（三步走，别一上来就写线上）

```bash
# 第 1 步：干跑。只打印、不写文件。首次联调必做。
python3 fetch_weather_alerts.py --dry-run

# 第 2 步：写到一个临时文件，肉眼核对 JSON 结构
python3 fetch_weather_alerts.py --out /tmp/alerts_preview.json
#   核对三个地方：weather.active_alerts、meta.weather_source、crops[0].alerts.risk

# 第 3 步：确认没问题再写线上（自动备份到 backups/data_weather_YYYY_MM_DD.json）
python3 fetch_weather_alerts.py
```

**脚本守则（与行情脚本一致）**：抓取/解析/配置任何一步失败 → **退出码 1，现有 `data.json` 一个字节都不动**，并在终端告诉你缺什么。
所以"没抓到"永远不会导致"预警被清空"。

三种"看起来都像没数据"的情况，脚本会严格区分（见自测【8】）：

| 情况 | 响应长什么样 | 脚本行为 |
|---|---|---|
| 接口通、当前**真的没有**预警 | 预警容器在，里面是空数组（`{"result":{"alert":{"status":"ok","content":[]}}}` 或 `{"status":"ok","warning":[]}`） | ✅ **算成功**：写 `alert_count=0`，摘掉上一次填进 `crops[].alerts` 的字符串，`meta.notes` 写"本次没有生效中的气象预警" |
| **没权限 / 结构不对**（拿不到预警容器） | 如彩云免费 token：`"result"` 里只有 `realtime`，没有 `alert` | ❌ 报错退出、不写文件，并给出开通指引（绝不伪装成"当前没有预警"） |
| **平台整体报错 / 限流** | `{"status":"failed","error":"Rate limit exceeded"}` | ❌ 报错退出、不写文件，原样带出平台错误信息 |

常见报错与处理：

| 终端提示 | 说明 | 怎么办 |
|---|---|---|
| 缺少 `APIHZ_ID / APIHZ_KEY` | 还没填账号 | 按第二节注册并填 `.env` |
| 还没有可用的预警接口地址 | `ALERT_APIHZ_ENDPOINT` 还是默认值 `tianqi` | 填真实路径名，或改用 `ALERT_API_URL` |
| 彩云…响应里没有 result.alert | **token 没有预警权限**（彩云预警是增值服务） | 控制台开通/升级预警数据；或改用 `apihz` / `generic` |
| 接口没返回预警数组（list_path=…） | 响应结构和你配的 `ALERT_JSON_PATH` 不一致 | 用 `--out /tmp/x.json` 抓下来看一眼，或先设 `ALERT_JSON_PATH` |
| 接口返回异常：status=failed / code=xxx | 平台侧报错（通常是 KEY 错 / 频次超限） | 看平台控制台；免费额度 10 次/分钟，别写循环里狂调 |

## 五、字段对不上怎么办（`ALERT_FIELD_MAP`）

脚本内置了常见字段名的自动识别（`severityColor` / `typeName` / `msg` / `fabutime` / `content` …），
如果某平台用了别的名字，**不改代码**，在 `.env` 里做一次映射即可（左=统一字段名，右=接口里的字段路径）：

```ini
ALERT_FIELD_MAP={"id":"warningId","title":"headline","type":"warningType","level":"warningLevel","text":"warningContent","advice":"defenseGuide","sender":"publishOrg","pub_time":"issueTime","expire":"expireTime"}
```

统一的字段名只有这些：
`id / title / type / level / color / sender / pub_time / effective / expire / text / advice / src`

- `level` 会自动清理成 `红色 / 橙色 / 黄色 / 蓝色 / 白色`（前端配色直接用这四个词）；
  平台用英文色名（彩云 v3 的 `level: "yellow"`）也能认；**字段缺失时还会从标题里认**（如「…发布大风蓝色预警[IV/一般]」→ `蓝色`，彩云 v2.6 就是这样）
- 时间字段（`pub_time / effective / expire`）会统一成 `YYYY-MM-DD HH:MM:SS`：
  **秒级时间戳**（彩云 v2.6 的 `pubtimestamp: 1640733900`）、**毫秒级时间戳**、`2026年09月19日 08:00`、ISO 带时区都能吃
- `color` 若平台没给，按等级自动补（红 `#E60012`、橙 `#FF8C00`、黄 `#FFD700`、蓝 `#1E90FF`）
- 过期的预警会被自动过滤（`--include-expired` 可保留，仅调试）；**没有有效期字段的**（如彩云 v2.6）不会被误判过期
- 类型（`type`）缺失时会从标题里认（暴雨 / 大风 / 高温 / 雷电 / 冰雹 / 大雾 …）

## 六、数据长什么样（前端怎么用）

```jsonc
{
  "meta": {
    // …原有字段不动…
    "weather_alert_count": 1,
    "weather_source": "接口盒子 apihz.cn（数据来源：中国气象局）",
    "weather_fetched_at": "2026-09-19 12:31:50",
    "weather_data_kind": "live",          // live=真实抓取，mock=模拟
    "sources": [ { "type": "weather_alert", "name": "...", "note": "预警数据版权归发布机构所有…" } ],
    "notes": [ "【气象预警】当前 1 条生效预警，最高等级：暴雨橙色预警（来源 …）。" ]
  },
  "weather": {                             // ★新增：结构化预警，供预警卡片/详情页/知识库引用
    "location": "山东省寿光市三元朱村", "lat": 36.88, "lon": 118.73,
    "provider": "apihz", "data_kind": "live", "fetched_at": "…", "alert_count": 1,
    "mirrored_to": "crops[].alerts.risk",
    "active_alerts": [ { "id": "…", "type": "暴雨", "level": "橙色", "color": "#FF8C00",
                         "sender": "寿光市气象台", "pub_time": "…", "effective": "…", "expire": "…",
                         "text": "…预警正文…", "advice": "…防御建议…", "src": "…" } ]
  },
  "crops": [
    { "name": "富强粉", "latest": 2.8, /* …行情字段不动… */
      "alerts": {
        "risk": ["【暴雨橙色预警】…（寿光市气象台 … 发布） 防御建议：…｜来源：…"],   // ★前端现在就能渲染（字符串数组）
        "price": [], "supply": []
      },
      "alerts_source": "接口盒子 apihz.cn", "alerts_updated_at": "2026-09-19 12:31:50" }
  ]
}
```

- 现有 `farm.html` / Next 前端把 `alerts.*` 当**字符串数组**迭代渲染，所以直接填进 `risk` 就能看到效果；
- 以后要做"预警卡片 + 颜色 + 倒计时"，读顶层 `weather.active_alerts` 即可（字段齐全，含颜色与过期时间）；
- 想换桶（比如放 `supply`）用 `--bucket supply` 或 `.env` 里的 `WEATHER_ALERT_BUCKET`。
