# 前端数据对接需求书

> **需求方**：数据端（`local_spider_v2.py`，产出 `data.json`）
> **接收方**：前端（Next.js 16 / React 19 / `next.config.ts` 里 `output: "export"`）
> **目标**：把「构建期写死的模拟行情」改成「运行时读取爬虫产出的 `/data.json`」，UI 设计与组件结构保持不变。

---

## 〇、先对齐三件事（否则会改错方向）

1. **现状是纯静态数据**：`src/lib/site-data.ts` 里 `PRICE_CROPS` 等常量在**构建时**被打进 bundle，全项目没有任何 `fetch`。所以爬虫更新了 `data.json`，只要不重新 `next build`，线上永远不变。
2. **因此必须改成运行时取数**：`data.json` 放在 `public/data.json` → 构建后自动变成 `out/data.json` → 浏览器直接访问 `https://域名/data.json` 拿到。（`public/` 是 Next 约定的静态资源目录，不需要任何额外配置。）
3. **这次只做"数据接入"，不动视觉**：样式、布局、组件划分全部照旧；数据从哪来、字段怎么映射由本文档规定。

### 2.1 新增 `src/lib/market-live.ts`（适配层，整个方案的核心）

```ts
"use client"

import { useEffect } from "react"
import { create } from "zustand"
import type { CropPrice } from "@/lib/site-data"

/* ---------- 1. 后端 data.json 的类型（对齐爬虫输出） ---------- */

export interface MarketMeta {
  location: string          // "山东省寿光市三元朱村"
  source: string            // 数据来源（可能含"演示数据"字样）
  stat_time: string         // "2026-09-18 07:00" ← 数据统计截止时间，图表锚点
  fetched_at: string
  generated_at?: string
  generated_by?: string
  series_days: number       // 当前已累积的真实天数
  series_target: number     // 目标天数（90）
  degraded: boolean         // true = 历史还没攒够
  freshness?: string
  notes?: string[]
}

export interface MarketCropRaw {
  name: string
  category: string
  grade?: string            // "标一" / "无"
  unit: string              // "元/公斤"
  volume?: string
  latest: number            // 最新价
  date: string              // "2026-09-18"
  series: number[]          // 真实历史（长度 = series_days）
  series_padded?: number[]  // 已补齐到 90，图表直接用
  analysis?: Partial<CropPrice["analysis"]>
  alerts?: Partial<CropPrice["alerts"]>
  stale?: boolean           // true = 本次抓取没拿到，价格沿用上一期
  last_updated?: string
}

export interface MarketFile {
  meta: MarketMeta
  crops: MarketCropRaw[]
}

/* ---------- 2. 缺字段时的兜底值（不让 UI 出现 undefined） ---------- */

const DEFAULT_ANALYSIS: CropPrice["analysis"] = {
  read: "该品种行情数据整理中。",
  supply: "供应情况整理中。",
  forecast: "暂无预测。",
  tip: "建议随行就市、分批出售。",
}
const DEFAULT_ALERTS: CropPrice["alerts"] = { price: [], supply: [], risk: [] }

/* ---------- 3. 把后端结构适配成现有组件要的 CropPrice ---------- */

export function toCropPrice(raw: MarketCropRaw): CropPrice {
  // 图表优先用 series_padded（后端已补齐到 90 天），没有则退回真实序列
  const series =
    raw.series_padded && raw.series_padded.length > 0
      ? raw.series_padded
      : (raw.series ?? [])

  return {
    name: raw.name,
    category: raw.category,
    unit: raw.unit || "元/公斤",
    volume: raw.volume || "—",
    series,
    analysis: { ...DEFAULT_ANALYSIS, ...(raw.analysis ?? {}) },
    alerts: { ...DEFAULT_ALERTS, ...(raw.alerts ?? {}) },
  }
}

/* ---------- 4. 取数：静态导出下就是请求 public/data.json ---------- */

export async function fetchMarket(): Promise<MarketFile> {
  // ?t=Date.now() 强制绕过 CDN/浏览器缓存，保证每次都是最新
  const res = await fetch(`/data.json?t=${Date.now()}`, { cache: "no-store" })
  if (!res.ok) throw new Error(`data.json 请求失败：${res.status}`)
  const json = (await res.json()) as MarketFile
  if (!json || !Array.isArray(json.crops)) throw new Error("data.json 结构不符合约定")
  return json
}

/* ---------- 5. 全局共享状态（沿用项目已有的 zustand 写法） ---------- */

interface MarketState {
  meta: MarketMeta | null
  crops: CropPrice[]          // 已适配好，可直接喂给现有组件
  loading: boolean
  error: string | null
  loadMarket: () => Promise<void>
}

export const useMarketStore = create<MarketState>((set) => ({
  meta: null,
  crops: [],
  loading: false,
  error: null,
  loadMarket: async () => {
    set({ loading: true, error: null })
    try {
      const file = await fetchMarket()
      set({
        meta: file.meta,
        crops: file.crops.map(toCropPrice),
        loading: false,
        error: null,
      })
    } catch (e) {
      // 注意：这里【不回退】到 site-data 里的模拟行情，
      // 否则会出现"页面有数据但其实是模拟值"的假象。
      set({ loading: false, error: e instanceof Error ? e.message : "数据加载失败" })
    }
  },
}))

/* ---------- 6. 图表数据：修掉原实现的越界问题 ---------- */

/**
 * 原实现：seriesDates(days).map((d,i) => crop.series[crop.series.length - days + i])
 * 当 series 比 days 短时索引会变成负数 → price 为 undefined → 图空白。
 * 这里改成「取真实存在的那一段，并把日期标签右对齐」。
 */
export function buildChartData(
  series: number[],
  days: number,
  labels: string[],
): { date: string; price: number }[] {
  const n = Math.max(1, Math.min(days, series.length))
  const prices = series.slice(series.length - n)
  const dates = labels.slice(Math.max(0, labels.length - n))
  return prices.map((price, i) => ({ date: dates[i] ?? "", price }))
}

/* ---------- 7. 页面里一次性触发加载 ---------- */

export function useLoadMarketOnce() {
  const loadMarket = useMarketStore((s) => s.loadMarket)
  useEffect(() => {
    void loadMarket()
  }, [loadMarket])
}
```

```ts
/* ① 分类白名单新增「粮油」——否则用户在下拉里永远选不到富强粉/晚籼米等 */
export const PRICE_CATEGORIES = ["传统农作物", "蔬菜", "畜禽", "水产", "粮油"]

/* ② seriesDates 支持传入锚点日期。默认值保持原样，确保其他调用点行为不变 */
export function seriesDates(days = 30, anchorISO?: string): string[] {
  const out: string[] = []
  // 原来写死 2026-08-27；现在可由调用方传入 meta.stat_time 的日期部分
  const end = new Date(anchorISO ? `${anchorISO}T00:00:00` : "2026-08-27T00:00:00")
  for (let i = days - 1; i >= 0; i--) {
    const d = new Date(end)
    d.setDate(end.getDate() - i)
    out.push(`${d.getMonth() + 1}/${d.getDate()}`)
  }
  return out
}

/* ③ 新增日期格式化函数（SITE_TODAY_LABEL 先保留，避免破坏其他引用） */
export function formatCnDate(iso?: string): string {
  const d = iso ? new Date(`${iso}T00:00:00`) : new Date("2026-08-27T00:00:00")
  return `${d.getFullYear()}年${d.getMonth() + 1}月${d.getDate()}日`
}
```

### 2.5 `src/lib/market-live.ts` 里再补一个"合并列表" hook

```ts
import { PRICE_CROPS } from "@/lib/site-data"

/** 实时品种 + 原有模拟品种。
 *  规则：实时数据覆盖到的分类（如「粮油」）整类用实时数据替换模拟数据；
 *        没覆盖到的分类继续用原有模拟数据，保证页面不空。 */
export function useAllPriceCrops() {
  const live = useMarketStore((s) => s.crops)
  const liveCategories = Array.from(new Set(live.map((c) => c.category)))
  const statics = PRICE_CROPS.filter((c) => !liveCategories.includes(c.category))
  return [...live, ...statics]
}
```

## 四、降级与兜底（前端必须处理这 5 种情况）

| # | 情况 | 前端表现要求 |
|---|---|---|
| 1 | `series_padded` 已补齐（`degraded=true`） | 图表正常画（是一条平线 + 最近几天有波动），**不要报错**；建议图下方加小灰字「历史数据累积中（N/90 天）」 |
| 2 | `series` 很短（甚至 1 个点） | 走 `buildChartData()` 的 clamp 逻辑，只画真实存在的部分，日期标签右对齐 |
| 3 | `alerts.*` 是空数组 | 不要出现"有标题没内容"的空卡片（见 2.7 第 1 条） |
| 4 | 某品种 `stale: true` | 在该品种价格旁标注「本次未更新，最后更新 X」，避免用户当成最新价 |
| 5 | `data.json` 请求失败 / 结构不对 | 显示错误 + 「重新尝试」按钮（现有逻辑已有）；**不要把 `site-data.ts` 的模拟行情当成"加载成功"混进来**，否则会出现"页面有数据但其实是模拟值"的假象 |

| 8 | `alerts` 为空数组时 | 预警区显示占位文案，而不是"有标题没内容"的空卡片 |

## 六、常见坑（踩了会浪费半天）

| 坑 | 说明 |
|---|---|
| **别把 `data.json` 放进 `src/` 用 `import` 引** | 那又是构建期固化，爬虫更新后必须重新 `next build`；必须放 **`public/data.json`** |
| **CDN 缓存** | 静态 JSON 会被 CDN/浏览器缓存，务必带 `?t=Date.now()`（参考 `fetchMarket()`） |
| **日期时区** | `new Date("2026-09-18")` 按 UTC 解析，东八区显示成 **9/17**；一律写成 `new Date("2026-09-18T00:00:00")` |
| **同名品种冲突** | 实时数据（粮油）与模拟数据的品种名不要重复，建议按"分类整类替换"（见 `useAllPriceCrops`） |
| **类型不用改** | 后端默认 `PAD_MODE=repeat`，`series_padded` 全是数字，`CropPrice.series: number[]` 保持不变 |
| **不要伪造"加载成功"** | 请求失败时不要回退到 `site-data.ts` 的模拟行情，否则用户/评委分不清哪些是真实数据 |

## 七、数据端配套（已同步交付 `local_spider_v2.py`）

- **输出位置**：根目录 `data.json`（留档）+ `public/data.json`（部署用）。上线时上传 `public/data.json` 即可（若静态托管根目录配的是项目根，则用根目录那份）。
- **怎么累积**：历史台账就存在 `data.json` 的 `crops[].history` 里，**每天跑一次脚本就自动向后累积**；同一天重复运行只更新当天价格，不产生重复点。
- **`degraded` 什么时候变 false**：累积满 90 天。在此之前图表靠 `series_padded` 的平线占位，页面加「历史数据累积中」提示即可。
- **答辩前建议**：至少提前跑 **7~10 天**，这样「近7日」就是一条真实曲线，演示效果最好。
